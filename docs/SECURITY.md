# SECURITY.md

## 安全目标

平台需保障用户身份、API Key、支付链路和调用数据安全，满足最小可运营合规要求。

## 基础控制

- API Key 仅存储摘要（`key_hash`），不明文持久化。
- 敏感配置（供应商密钥、支付密钥）必须通过环境变量或密钥管理服务注入。
- 所有对外接口必须有 TraceID，便于审计追踪。
- 登录、支付、提现等高风险操作启用二次校验（验证码/风控挑战）。

## 数据保护

- 用户敏感数据落库前做脱敏或加密处理。
- 日志中禁止输出密钥、完整手机号、完整身份证号、完整支付凭证。
- 审计日志只增不改，保留策略按合规要求配置。

## 供应商调用安全

- 统一超时、重试和熔断策略，避免放大故障。
- 对供应商返回内容进行安全过滤与错误归一。
- 支持按租户或用户级别进行调用频控和封禁。

## 支付与账务安全

- 支付回调使用签名校验 + 幂等键。
- 账务流水与调用订单保持可核对关系。
- 日终自动对账，异常单进入补偿队列。

## 漏洞响应流程

1. 记录问题并分级（P0-P3）。
2. P0/P1 立即止血并发布公告。
3. 修复后补充测试与复盘文档。
