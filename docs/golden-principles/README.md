# 黄金原则

## 适用于本仓库的工程原则

1. **地图优先**：先补文档地图，再写代码细节。
2. **边界可执行**：分层约束必须由脚本/CI执行，不只停留在文档。
3. **错误可修复**：检查脚本输出要包含修复建议。
4. **渐进收敛**：允许历史问题存在，但新改动不能新增违规。
5. **简单可靠**：优先使用团队熟悉、可维护的技术方案。
6. **安全默认开启**：涉及账号、支付、密钥链路必须走安全基线。
