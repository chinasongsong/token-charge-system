# TDD 目录说明（技术设计文档）

本目录存放**可指导实现与测试**的技术设计文档（TDD = Technical Design Document，与「测试驱动开发」缩写同名时，在本仓库特指 **Technical Design**）。文档与 `docs/dev-plan.md` **§2.3 优化项 backlog（O-1～O-9）** 对齐。

## 标准目录（直接套用）

在 `docs/TDD/` 下为每个主题建独立 Markdown 文件，命名建议：

```text
docs/TDD/
  README.md                          # 本说明 + 索引
  _template/
    技术设计文档模板.md               # 全量章节骨架，新建设计时复制后改文件名
  O-01-扣费并发-分布式锁与悲观锁策略.md
  O-02-异步账务-Outbox与MQ.md
  O-03-预占额度与冲正-流式联动.md
  O-04-渠道对账与调账闭环.md
  O-05-Redis缓存-APIKey解析与余额.md
  O-06-网关风控-IP与配额.md
  O-07-APIKey生命周期-过期与轮换.md
  O-08-支付补偿-渠道查单与重试入账.md
  O-09-读扩展-读写分离与热点缓存.md
```

新建主题时：**复制** `_template/技术设计文档模板.md` → 按 `O-xx-简述.md` 或业务名命名 → 逐节填写；**禁止**删除章节标题（无内容可写「暂无 / 不适用」并简述原因）。

## 文档信息（元数据）约定

每篇设计文首须包含（可复制模板内表格）：

| 字段 | 说明 |
|------|------|
| 文档版本 | SemVer 或 `v0.1` 草案递增 |
| 作者 | 责任人花名/邮箱 |
| 创建 / 更新日期 | ISO 8601 日期 |
| 业务域 | 如：计费 / 支付 / 网关 / 适配器 |
| 关联 backlog | 如：`dev-plan.md` §2.3 **O-x** |
| 评审状态 | 草案 / 评审中 / 已批准 |

## 与 `dev-plan.md` 的关系

- **路线图与阶段勾选**：仍以 `docs/dev-plan.md` 为唯一权威。
- **本目录**：承载 O-x 对应的**展开设计**；某 O-x 在 dev-plan 勾选完成后，应在同一轮或紧随提交中**更新本文档版本号与「实现对照」小节**（若模板含该小节，可自行追加）。
- **架构侧总表（状态 / 验收 / 收口流程）**：见 [`docs/architecture/技术负债与路线图.md`](../architecture/技术负债与路线图.md)。
