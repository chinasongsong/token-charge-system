# 路由与配置

配置文件：`adapter-service/src/main/resources/application.yml`

---

## 1. 服务端口与数据源

```1:15:adapter-service/src/main/resources/application.yml
server:
  port: 8102

spring:
  application:
    name: adapter-service
  datasource:
    url: ${MYSQL_JDBC_URL:jdbc:mysql://127.0.0.1:3306/token_charge?...}
    username: ${MYSQL_USERNAME:root}
    password: ${MYSQL_PASSWORD:change-me}
```

| 项 | 默认 | 说明 |
|----|------|------|
| `server.port` | **8102** | 与网关 `TOKENS_GATEWAY_ADAPTER_URI` 一致 |
| MySQL | `token_charge` | `model_providers`、`risk_events` |

---

## 2. 网关路由关系（平台级）

adapter **不**定义 Spring Cloud Gateway 路由；由 `gateway-service` 转发：

| 网关 route id | Path | 下游 |
|---------------|------|------|
| `adapter-v1` | `/v1/**` | `TOKENS_GATEWAY_ADAPTER_URI` → 默认 `http://127.0.0.1:8102` |

更具体的 `/v1/usage` 等路由在 billing，**不会**进入 adapter（须在 `/v1/**` 之前声明，见 gateway [08-路由与配置.md](../../gateway-service/docs/08-路由与配置.md)）。

## 3. tokenhub.adapter 业务配置

```17:31:adapter-service/src/main/resources/application.yml
tokenhub:
  adapter:
    provider-code: deepseek
    default-chat-model: deepseek-v4-flash
    deepseek-api-key: ${DEEPSEEK_API_KEY:}
    deepseek-base-url-fallback: ${DEEPSEEK_BASE_URL_FALLBACK:https://api.deepseek.com}
    failover-enabled: ${ADAPTER_FAILOVER_ENABLED:true}
    zhipu-provider-code: zhipu
    zhipu-api-key: ${ZHIPU_API_KEY:}
    zhipu-base-url-fallback: ${ZHIPU_BASE_URL_FALLBACK:https://open.bigmodel.cn/api/paas/v4}
    zhipu-default-chat-model: glm-4-flash
    routing:
      weight-deepseek: ${ROUTING_WEIGHT_DEEPSEEK:70}
      weight-zhipu: ${ROUTING_WEIGHT_ZHIPU:30}
```

| 配置键 | 环境变量 | 默认 | 说明 |
|--------|----------|------|------|
| `provider-code` | — | `deepseek` | DeepSeek 供应商标识 / 结算默认 provider |
| `default-chat-model` | — | `deepseek-v4-flash` | 空 model 时默认值 |
| `deepseek-api-key` | `DEEPSEEK_API_KEY` | 空 | **生产必填** |
| `deepseek-base-url-fallback` | `DEEPSEEK_BASE_URL_FALLBACK` | `https://api.deepseek.com` | DB 不可用时的 base |
| `failover-enabled` | `ADAPTER_FAILOVER_ENABLED` | `true` | 是否启用供应商故障转移 |
| `zhipu-provider-code` | — | `zhipu` | 智谱 code |
| `zhipu-api-key` | `ZHIPU_API_KEY` | 空 | 空则不加权智谱、不作 secondary |
| `zhipu-base-url-fallback` | `ZHIPU_BASE_URL_FALLBACK` | 智谱 v4 base | |
| `zhipu-default-chat-model` | — | `glm-4-flash` | failover 到智谱时强制 model |
| `routing.weight-deepseek` | `ROUTING_WEIGHT_DEEPSEEK` | `70` | 加权首跳 |
| `routing.weight-zhipu` | `ROUTING_WEIGHT_ZHIPU` | `30` | 加权首跳 |

## 5. Resilience4j

```36:49:adapter-service/src/main/resources/application.yml
resilience4j:
  circuitbreaker:
    instances:
      deepseek:
        registerHealthIndicator: true
        slidingWindowSize: 20
        minimumNumberOfCalls: 5
        failureRateThreshold: 50
        waitDurationInOpenState: 15s
  retry:
    instances:
      deepseek:
        maxAttempts: 2
        waitDuration: 200ms
```

### 5.1 熔断器 `deepseek`（已接入代码）

| 参数 | 值 | 含义 |
|------|-----|------|
| `slidingWindowSize` | 20 | 滑动窗口内统计失败率 |
| `minimumNumberOfCalls` | 5 | 至少 5 次调用后才可开路 |
| `failureRateThreshold` | 50 | 失败率 ≥ 50% 触发 OPEN |
| `waitDurationInOpenState` | 15s | OPEN 后 15s 进入半开 |
| `registerHealthIndicator` | true | 可通过 Actuator 观察状态 |

**代码绑定**：`FailoverRoutingAdapter` 通过 `CircuitBreakerRegistry.circuitBreaker("deepseek")` 包裹 **DeepSeek** 的 `chat` 调用。OPEN 时抛出 `CallNotPermittedException`，视为可恢复，可触发向智谱 failover。

### 5.2 重试 `deepseek`（仅配置，未绑定）

`resilience4j.retry.instances.deepseek` 已在 yml 声明，但当前 Java **未**使用 `@Retry` 或 `Retry.decorateCallable`。实际重试语义由 **failover 到对端供应商** 承担。若需同供应商瞬时重试，应在 `DeepSeekProviderAdapter` 或 `FailoverRoutingAdapter` 显式接入 Retry API。

## 6. HTTP 客户端超时

`AdapterHttpConfiguration` 定义 `adapterRestTemplate`：

| 项 | 值 |
|----|-----|
| 连接超时 | 15s |
| 读超时 | 3 分钟 |

用于上游 Chat 与 billing settle；长推理场景依赖读超时，勿在生产误设过短。

## 8. 本地联调最小环境变量

| 变量 | 用途 |
|------|------|
| `DEEPSEEK_API_KEY` | DeepSeek 主路径 |
| `ZHIPU_API_KEY` | 加权 / failover 至智谱（可选） |
| `MYSQL_JDBC_URL` / `MYSQL_USERNAME` / `MYSQL_PASSWORD` | `model_providers`、`risk_events` |
| `TOKENS_GATEWAY_BILLING_URI` | 结算 base URL |
| `BILLING_INTERNAL_TOKEN` | 与 billing 一致 |
| `ADAPTER_FAILOVER_ENABLED` | 关闭可仅测单供应商 |
| `ROUTING_WEIGHT_DEEPSEEK` / `ROUTING_WEIGHT_ZHIPU` | 调流量比例 |

经完整链路联调时，还需网关侧：`JWT_SECRET` 或 API Key、`REDIS_*` 等（见 gateway 文档）。

## 10. 业界配置方案对比

| 方案 | 适用 |
|------|------|
| **YAML + 环境变量（当前）** | 单集群、供应商少 |
| **Nacos / Spring Cloud Config** | 多环境、动态调权重 |
| **K8s ConfigMap + Secret** | Key 与 URL 分 Secret 管理 |
| **专用路由控制面** | 多 region、多模型矩阵 |

演进建议：权重与 failover 开关迁入配置中心；Retry 与 CircuitBreaker 统一由 Resilience4j 注解或 AOP 声明在 `ProviderAdapter` 实现类上。
